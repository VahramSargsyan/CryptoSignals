## Candidate

`DEFENSIVE_LOW_VOL_CRYPTO_ROUTER_REACTIVATION_V3`

Entry remains unchanged:

1. Universe = ATOM, TWT, PEPE, BNB, SOL, TRX, AAVE, LINK.

3. Market breadth = count of 8 assets above own causal SMA200.
4. Enter defensive mode after 3 consecutive closes with breadth <= 3.
5. Defensive asset = lowest trailing 30d realized-volatility token.
6. Hold that token while defensive.
7. Shadow relative router continues normally.

Exit changes qualitatively:

8. Ignore breadth for EXIT.
9. Ignore SMA of the shadow target for EXIT.
10. The first NEW confirmed outbound transition generated by the shadow router AFTER defensive entry is treated as router reactivation.
11. At the next daily open, update the shadow target and simultaneously exit defensive mode into that new shadow target.
12. A shadow transition already pending before the defensive entry does NOT count as reactivation.
13. After re-entry, the original defensive-entry rule may trigger again if breadth remains <= 3 for 3 closes.
14. Apply 0.1% cost to every actual transition.
15. No USDT.

No new tunable number is introduced by V3.

## Causal rationale

The dominant failure mode of the base router was stale holding: the network could become silent while the held token fell.

The defensive layer is meant to cover periods where the relative network is effectively not providing useful action.

Therefore a new confirmed relative transition is treated as evidence that the router has become active again.

This tests network reactivation directly instead of waiting for broad absolute recovery.

   No ORIGINAL-defense positive 180d window may become a V3 return below -10%.

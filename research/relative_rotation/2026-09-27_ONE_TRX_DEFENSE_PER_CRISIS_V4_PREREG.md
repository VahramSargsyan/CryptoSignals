## Purpose

Test the user's clarified architecture:

- TRX acts as the defensive holding during the first phase of a crypto crisis;
- the relative router continues in shadow while actual capital is in TRX;
- when the shadow router produces its first NEW confirmed outbound transition after defensive entry, actual capital moves directly from TRX into the new target;
- the system does NOT route TRX -> old shadow asset -> new target;
- after that first router-reactivation exit, ordinary relative rotations resume;
- another TRX defense is forbidden until the old crisis is formally over;
- the crisis detector re-arms only after breadth >=5 for 3 consecutive closes;
- after re-arm, a future crisis requires a completely fresh breadth <=3 x3 confirmation.

This changes the old V3 failure mode by allowing only ONE TRX defensive reaction per crisis episode.

## Frozen entry rule

Unchanged:
- universe = ATOM, TWT, PEPE, BNB, SOL, TRX, AAVE, LINK;
- relative router = existing frozen router;
- market breadth = number of assets above own causal SMA200;
- enter crisis after 3 consecutive closes breadth <=3;
- execute TRX defense at next daily open;
- 0.1% actual transition cost;
- shadow router continues normally.

TRX is fixed as the defensive asset in this experiment.

## Defensive exit / router reactivation

While in TRX defense:

1. Ignore breadth for defensive EXIT.
2. Wait for the first NEW confirmed outbound transition generated by the shadow router after defensive entry.
3. At the next daily open:
   - update shadow target;
   - move actual capital directly from TRX into that new shadow target;
   - do not route through the prior shadow asset.
4. Transition to POST_TRX_DISARMED.

A shadow transition already pending before defensive entry does not count as router reactivation.

If the new shadow target is TRX itself, the state still transitions to POST_TRX_DISARMED but no extra actual trade/cost is charged because actual asset already equals target.

## Post-defense state

POST_TRX_DISARMED:

- actual capital follows ordinary relative-router transitions;
- no new TRX defense can trigger;
- low-stress entry streak is not accumulated;
- breadth is watched only for crisis completion.

Re-arm condition:
- breadth >=5 for 3 consecutive closes.

After re-arm:
- state = ARMED;
- recovery and low-stress streaks reset;
- a new TRX defense requires a completely fresh breadth <=3 x3 sequence.

Thus:
- router activity can end TRX defense;
- broad recovery is required only to allow the NEXT defensive episode.

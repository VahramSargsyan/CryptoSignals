## Objective

Test one emergency re-entry fallback on top of the current research baseline:

CONTROL:
- single selected-month surge >=95%;
- P1 cash-out after >=5% pullback;
- sell 30%;
- normal 5-bar fractal buy-stop re-entry.

CANDIDATE:
- identical CONTROL;
- if cash is still parked 15 calendar days after actual cash-out:
  - recovery reference level = 98% of frozen-U10 reference open equity at cash-out;
  - if reference close at eligibility is already >= recovery level, schedule full re-entry next open;
  - otherwise wait for the first close crossing from below to >= recovery level and re-enter next open.

No parameter sweep.

## Causal execution semantics

Fallback signals are generated only at daily closes.

If fallback was signaled at the previous close:
- it executes at the current open before any current-session fractal intraday-high fill can be observed.

Otherwise:
- the existing fractal buy-stop can fill at current open/high.

This prevents intraday lookahead.

## Critical finding: the intended recovery-cross never happened

The intended idea was:

> after 15 days, if still in cash, use a recovery threshold near the sale level so that a renewed uptrend does not leave cash behind.

But historically every fallback-eligible cycle had reference close already above the 98% recovery level at first eligibility.

For all 554 fallback cycles:
- fallback executed as RECOVERY_IMMEDIATE;
- none executed as RECOVERY_CROSS;
- fallback cash-cycle duration was exactly 16 days in every case.

Reference close / recovery-level ratio at eligibility:
- minimum: about 1.021
- median: about 1.145
- maximum: about 1.305

Thus even the closest case was already ~2.1% ABOVE the recovery threshold by day 15.

The 15-day + 98% rule therefore did not behave like a conditional recovery stop.

It behaved like:

> force re-entry on roughly day 16 whenever the normal fractal has not already completed.

## Interpretation

The future-risk question was valid:

> What if 30% is sold and the normal fractal re-entry fails to complete while the market runs away upward?

However, the tested fallback does not solve that problem cleanly.

At 15 days / 98%:
- the reference had already recovered above the fallback threshold in every eligible historical case;
- therefore the rule became a fixed-time forced re-entry;
- this interrupted profitable longer cash waits;
- it reduced terminal performance in the majority of affected topologies.

## Decision

Reject this exact fallback:

- 15 calendar days;
- 98% of cash-out U10-reference open;
- immediate next-open re-entry when already above threshold.

Do not promote it.

Retain CONTROL:
- SURGE95
- P1
- 30% cash
- 5-bar fractal buy-stop
- no timeout fallback

as the stronger current research baseline.

## Research implication

The historical evidence does NOT show a stranded-cash problem:
- CONTROL had 0 unfinished cycles in canonical U10;
- CONTROL had 0 unfinished cycles across all 791 alternatives.

Therefore a fallback should not be added merely because a future stranded-cash state is imaginable.

If future paper/live research actually produces an unresolved cash cycle, that event would provide cleaner evidence for designing a guardrail than forcing an arbitrary historical timeout.
